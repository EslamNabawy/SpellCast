Scope read fully: `script.js` (2552 lines), `index.html`, `style.css`, `tools/qa/session.mjs`,

Report only — no code changed. Findings numbered. Say "fix 2 and 5" to act on any subset.

## What this repo does

A single-user, client-side spelling-practice app. GitHub Pages serves four files
(`index.html`, `style.css`, `script.js`, `words.js`); everything — words, SRS deck,
stats, settings — lives in the visitor's `localStorage`. No backend, no accounts,
no paid actions. Load assumed: one person on one browser; peak work an imported
word list of ~5,000 words.

## Must fix

1. **A corrupted saved value makes the whole app dead** (`script.js:1076-1107`)
   - **What this is:** `loadAllPersisted()` loads every saved setting and the word deck from localStorage at boot.
   - **Problem:** It trusts the shapes. `loadLocal` only catches JSON parse errors, so `"bucket": {}` (object instead of array) or `"srsCards": "x"` throws inside `init()` — before anything renders. The app is a blank card until the user clears site data by hand, and their SRS progress goes with it.
   - **Fix:** Type-guard each read: arrays for `bucket`/`customWords`, object for `srsCards`, finite numbers for counts/duration/volume, one of the known strings for category/difficulty/review mode. Fall back to the default when wrong.
   - **If we skip it:** Any future schema bug or a stray old key bricks the app for that visitor, silently.

## Should fix

2. **Esc over the Data page also skips the current word** (`script.js:2630`, `script.js:2776-2790`)
   - **What this is:** Two document-level `keydown` listeners both watch Escape: one closes the data page, one drives the game.
   - **Problem:** Neither knows about the other. With a word in the type phase and the Data page open, one Esc press closes the page *and* hits `skipBtn.click()` — the word is silently skipped: bucket entry, SRS lapse, "words practiced" all tick up.
   - **Fix:** In the global handler, `return` when `!dom.dataPage.hidden` (the dedicated data-page handler already closes it).
   - **If we skip it:** Every Esc on that page costs a practice word.

3. **A big import freezes the page** (`script.js:1513-1528` → `1038-1057`)
   - **What this is:** Bulk import loops rows through `addCustomWord`.
   - **Problem:** Each row does a full `renderCustomWordsList` innerHTML rebuild, a `renderSrsStats`, a `resetWordPool`, and two localStorage writes. 5,000 rows = 5,000 full re-renders + 10,000 saves — a multi-second freeze with the tab unresponsive.
   - **Fix:** Collect rows first, then one `saveCustomWords`+`saveSrsCards`, one render of each list, one `resetWordPool` at the end.
   - **If we skip it:** Power users importing real word lists think the site crashed.

4. **The row cap only guards two of three import formats** (`script.js:1379-1394`, cap check at `1440-1444`)
   - **What this is:** `IMPORT_MAX_ROWS = 5000` limits CSV and parsed-paste rows.
   - **Problem:** The JSON import path never checks it, and pasted text has no size limit at all (file path has a 2 MB guard; paste doesn't). A huge pasted JSON parses and loops unbounded.
   - **Fix:** Apply the row cap in `jsonImportRows`, cap paste length ~2 MB before parse.
   - **If we skip it:** One paste can hang a phone.

5. **Deleting a "My words" word leaves it in the practice bucket** (`script.js:1059-1074`)
   - **What this is:** `deleteCustomWord` removes the word from the list, WORDS, and the SRS deck.
   - **Problem:** It never touches `state.bucket`, so a word the user already missed keeps showing in the bucket panel and can be picked for practice — with its SRS record already gone.
   - **Fix:** filter it out of `state.bucket` and `saveBucket` in `deleteCustomWord`.
   - **If we skip it:** The bucket shows ghosts the user deliberately deleted.

6. **The mobile keyboard fix has no repeatable coverage** (`tools/qa/scratch/probe-v39.mjs`, `probe-v40.mjs`)
   - **What this is:** The v39/v40 keyboard-anchor logic is the most device-fragile code in the app, proven only by two scratch probes.
   - **Problem:** The probes are untracked files, and `run-all.mjs` never runs them. Any refactor or tidy-up can kill the #1 mobile fix with a green gate.
   - **Fix:** Track the two probes and add a `keyboard` script to the gate chain (they run in seconds).
   - **If we skip it:** The next release can silently regress what the user just had us fix three times.

7. **The repo ships a second, unstale copy of every QA report** (`tools/qa/test-results/*.json`)
   - **What this is:** Every gate run rewrites reports; a generated copy ~130 KB is committed, duplicating `docs/baseline/*.json`.
   - **Problem:** Two copies must change together; git history is full of generated noise.
   - **Fix:** Delete `tools/qa/test-results/` and git-ignore it; keep `docs/baseline/` as the tracked record. Also drop the one-off `debug-*.mjs` in `scratch/`.
   - **If we skip it:** Reviewers diff generated JSON and miss real changes.

## Nice to have

8. **`dom.checkBtn` fallback runs every viewport tick** (`script.js:643`)
   - **What this is:** The keyboard anchor falls back to `document.getElementById("checkBtn")` each call.
   - **Problem:** Minor wasted query and it hides when a ref is missing.
   - **Fix:** Add it to the `dom` refs. One line.

9. **The import-example CSS is declared twice** (`style.css:374-376` vs `:429-431`)
   - **What this is:** v38 appended a second base block instead of editing the original, so `.import-example` rules now cascade over each other.
   - **Problem:** Must change together; the later block wins only by file order.
   - **Fix:** Merge into one block next time that area is touched.

10. **The reveal timer keeps running behind overlays** (`beginRound`/`runSeeTimer`, `script.js:760-820`)
   - **What this is:** Opening the Data page or the summary overlay doesn't pause the see-clock.
   - **Problem:** The word times out and the phase flips behind a full-screen overlay; when you close the page you land mid-phase unexpectedly.
   - **Fix:** Pause the see timer (and session clock) when an overlay opens, resume on close.
   - **If we skip it:** Occasional "it skipped by itself" confusion.

## Verified-safe (checked, nothing to report)

All user-text render paths escape or regex-validate (`renderWordDisplay`, bucket/SRS/category lists, toasts, labels via `sanitizeLabel`); import words must match `^[a-z'-]{2,30}$`. The deploy workflow publishes only the four app files + assets — docs, harness and probes are not public. Reset-all requires typing DELETE. Dialog focus trap, hash routing, and the 2 MB file guard all check out. The `runSeeTimer`→`goToTypePhase` path and the fixture byte-for-byte save discipline are sound.

## Verdict

Healthy app, one silent-failure root (finding 1) worth fixing first.
Lean: 0 runtime dependencies (already minimal); ~135 KB and 8 dead dev files droppable (finding 7).
